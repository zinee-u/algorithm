# 2026-Q3 코딩 연습

사용자 기억을 바탕으로 조건을 정리한 연습 문제 다섯 개입니다. 스티커 교환은 원래 시험의 열 교환 제한이 불확실하여 두 문항으로 나누었습니다. 공식 출제문이나 공식 채점 데이터가 아닙니다. 모호한 조건은 문항별 복원 가정에 명시했으며, 이 문제집의 테스트는 그 규칙을 따릅니다.

## 2번 · 가장 마음에 드는 체험 부스 제한사항

- 2 ≤ `preferences`의 길이 ≤ 3,000
  - 같은 이름이 중복해서 주어지지 않습니다.
  - 배열의 뒤에 있는 부스일수록 선호도가 높습니다.
- 1 ≤ 부스 이름의 길이 ≤ 10
  - 부스 이름은 영문 알파벳으로만 이루어져 있으며, 대소문자를 구분합니다.
- 1 ≤ `requests`의 길이 ≤ 3,000
  - `requests[i] = [start, end, receive, give]`이며, 각 원소는 문자열입니다.
  - `start`, `end`: 교환 시작 시각, 마감 시각
  - `receive`, `give`: 내가 받을 부스, 내가 건넬 부스
  - 교환 방향은 `give → receive`입니다.
  - 제안의 입력 순서는 교환 순서와 무관합니다.
  - 두 부스 중 하나라도 `preferences`에 없으면 해당 제안 전체를 제외합니다.
- `start`와 `end`는 `HH:MM` 형식입니다.
  - `00 ≤ HH ≤ 23`, `00 ≤ MM ≤ 59`
  - `start < end`이며, 모든 시각은 같은 날입니다.
  - `start ≤ 교환 시각 ≤ end`일 때 교환할 수 있습니다. (양 끝 시각 포함)
- `00:00`에 `preferences[0]`의 이용권 한 장으로 시작합니다.
  - 항상 이용권 한 장만 보유합니다.
  - 교환하면 기존 이용권은 사라집니다.
- 교환에 걸리는 시간은 0입니다.
  - 같은 시각에 여러 번 연속으로 교환할 수 있습니다.
  - 이용권을 가진 채 기다릴 수 있습니다.
  - 시간을 거슬러 교환할 수는 없습니다.
- 중간에 선호도가 낮은 부스로 바꾸어도 됩니다.
  - 교환하지 않거나 원하는 시점에 중단해도 됩니다.
- 얻을 수 있는 이용권 중 가장 선호하는 부스 이름을 문자열로 반환합니다.
  - 표준 입력·출력 대신 `solution(preferences, requests)`의 반환값을 작성합니다.

## 3번 · 스티커 교환 (다른 열 허용) 제한사항

- `sticker`와 `target`은 동일한 크기의 `N × M` 직사각형 배열이며, 모든 값은 `0` 또는 `1`입니다.
- **연습용 입력 범위:** `1 ≤ N, M ≤ 10`, `N × M ≤ 12`.
  - 원래 시험에서 `N`과 `M` 각각의 상한이 작았다는 기억은 있으나, 정확한 상한은 확인되지 않았습니다.
  - `N × M ≤ 12`는 작은 배치를 탐색하는 연습을 위해 추가한 조건입니다.
- 한 번의 교환에서는 서로 다른 두 행에서 위치를 하나씩 골라 값을 맞바꿉니다.
  - 서로 다른 열끼리도 교환할 수 있습니다.
  - 같은 행의 두 위치를 직접 교환할 수는 없습니다.
  - 이미 목표와 일치한 위치도 사용할 수 있습니다.
- 각 위치가 `target`과 일치하도록 만드는 최소 교환 횟수를 정수로 반환합니다. 이미 같으면 `0`입니다.
- 허용된 교환으로 목표를 만들 수 없다면 `-1`을 반환합니다. 불가능한 입력도 주어집니다.
  - `N = 1`이면 처음부터 같을 때만 `0`이며, 다르면 `-1`입니다.
- 열 교환 제한은 원래 시험에서 확인된 조건이 아닙니다. 같은 열만 허용하는 연습판은 5번 문항으로 분리했습니다.
- [문제 설명과 자체 복원 예제 8개](03-sticker-exchange/problem.md)를 참고하세요.

## 4번 · 숫자의 이동과 합치지 제한사항

- **연습용 입력 범위:** `1 ≤ len(numbers) ≤ 100,000`, `-10^9 ≤ numbers[i] ≤ 10^9`.
  - 원래 시험의 입력 상한은 확인되지 않았습니다.
- 매 시간 모든 양수는 오른쪽으로 한 칸, 모든 음수는 왼쪽으로 한 칸 **동시에** 이동합니다.
- 이동을 마친 뒤 같은 칸에 도착한 숫자만 합쳐집니다. 이동 중 엇갈려 지나간 숫자는 합쳐지지 않습니다.
  - 합이 `0`이면 사라지고, 그렇지 않으면 다음 시간부터 합의 부호에 따라 이동합니다.
  - `0`은 움직이는 숫자가 아니라 빈 칸입니다.
- 경계를 넘어간 숫자는 사라집니다. 모든 숫자가 사라질 때까지 진행합니다.
- `[왼쪽으로 나간 숫자의 개수, 오른쪽으로 나간 숫자의 개수]`를 반환합니다.
  - 합쳐진 숫자도 탈출할 때 하나로 셉니다. 합이 `0`이 되어 사라진 숫자는 세지 않습니다.
  - 처음부터 모두 `0`이면 `[0, 0]`입니다.
- 기억한 시험 제한은 **10초·2GB**입니다. 확인된 공식 제한은 아니며, 연습용 채점기는 메모리 상한을 강제하지 않습니다.
- [문제 설명과 자체 복원 예제](04-number-movement/problem.md)에 규칙의 확인 범위와 반환 순서에 관한 복원 조건을 정리했습니다.

## 5번 · 스티커 교환 (같은 열만) 제한사항

- `sticker`와 `target`은 동일한 크기의 `N × M` 직사각형 배열이며, 모든 값은 `0` 또는 `1`입니다.
- **연습용 입력 범위:** `1 ≤ N, M ≤ 10`. 최대 `10 × 10` 배열입니다.
  - 원래 시험의 정확한 입력 상한과 열 교환 제한은 확인되지 않았습니다.
- 한 번의 교환에서는 **서로 다른 두 행의 같은 열**에 있는 스티커를 맞바꿉니다.
  - 다른 열 사이의 교환과 같은 행 안의 교환은 허용하지 않습니다.
  - 이미 목표와 일치한 위치도 사용할 수 있습니다.
- 모든 위치가 `target`과 같아지는 최소 교환 횟수를 반환합니다. 이미 같으면 `0`, 불가능하면 `-1`입니다.
- 3번과 5번은 서로 다른 교환 규칙을 정한 별도 연습판입니다. 각 문항의 규칙으로 구현하고 채점하세요.
- [문제 설명과 자체 복원 예제](05-sticker-same-column/problem.md)를 참고하세요.

## 풀고 PR 보내기

1. 이 저장소를 fork하고 자신의 브랜치를 만듭니다.
2. `submissions/<GitHub ID>/` 아래에 문항 번호에 맞는 `.py` 또는 `.cpp` 답안을 작성합니다.
3. 로컬 채점기로 공개 테스트 10개를 실행합니다.
4. 구현과 테스트 결과를 담아 원래 저장소로 PR을 보냅니다.

자세한 경로, 함수 형식, 명령은 [제출 안내](CONTRIBUTING.md)를 참고하세요. 기준 해설과 정답 코드는 공개하지 않습니다.

## 입출력 테스트

문항마다 **10개**, 총 **50개**의 재현 가능한 입력·기대 출력이 있습니다. [테스트 목록](TESTCASES.md)에서 각 사례가 확인하는 경계 조건과 크기를 볼 수 있습니다.

이 디렉터리에서 다음 명령으로 실제 JSON 입출력 파일을 생성합니다.

```sh
python3 cases.py --output generated-tests
```

`generated-tests/<문항 ID>/01.in.json`부터 `10.in.json`까지 입력을, 같은 이름의 `.out.json`에 기대 반환값을 만듭니다. 백만 칸 격자도 생성되므로 큰 입력 내용을 Markdown에 직접 나열하지 않습니다. 채점기는 같은 생성기를 사용하며 파일을 미리 만들 필요는 없습니다.

```sh
python3 check.py 01-square-regions submissions/YOUR_ID/01-square-regions.py --timeout 5
python3 check.py 02-ticket-exchange submissions/YOUR_ID/02-ticket-exchange.cpp --timeout 5
python3 check.py 03-sticker-exchange submissions/YOUR_ID/03-sticker-exchange.py --timeout 5
python3 check.py 04-number-movement submissions/YOUR_ID/04-number-movement.py --timeout 10
python3 check.py 05-sticker-same-column submissions/YOUR_ID/05-sticker-same-column.py --timeout 5
```

최대 크기 입력과 테스트별 시간제한으로 느린 구현을 점검할 수 있습니다. 기본 제한은 이 문제집의 로컬 실행 기준이며 실제 시험의 시간제한이 아닙니다. 공개 사례 통과가 모든 입력의 정답이나 시간복잡도를 보장하지는 않습니다.
