# 테스트 케이스

문항마다 **정확히 10개**의 입력과 기대 출력을 제공합니다. 공식 시험 데이터가 아니라 이 저장소의 재구성 규칙을 검증하기 위해 만든 데이터입니다. 기대값은 입력의 구조를 근거로 고정했으며, 생성기가 정답 풀이를 실행해 출력값을 만들지는 않습니다.

[cases.py](cases.py)는 표준 라이브러리만 사용합니다. 이 파일이 있는 디렉터리에서 다음 명령을 실행하면 큰 입력까지 포함한 JSON 파일을 실제로 생성합니다.

```bash
python3 cases.py --output generated-tests
```

각 문항에 `01`부터 `10`까지 입력·출력 쌍이 생깁니다. 다섯 문항을 합쳐 입력 50개와 출력 50개, 총 100개 파일입니다.

```text
generated-tests/
  01-square-regions/
    01.in.json
    01.out.json
    ...
    10.in.json
    10.out.json
  02-ticket-exchange/
    01.in.json
    01.out.json
    ...
    10.in.json
    10.out.json
  03-sticker-exchange/
    01.in.json
    01.out.json
    ...
    10.in.json
    10.out.json
  04-number-movement/
    01.in.json
    01.out.json
    ...
    10.in.json
    10.out.json
  05-sticker-same-column/
    01.in.json
    01.out.json
    ...
    10.in.json
    10.out.json
```

입력 JSON은 함수 인자의 목록을 `args`에 담습니다. 출력 JSON은 함수가 반환해야 하는 정수, 문자열 또는 정수 배열입니다. 예를 들어 첫 문항의 1번 입력과 출력은 다음과 같습니다.

```json
{"args":[[[1,2],[3,4]]]}
```

```json
0
```

두 번째 문항은 `{"args":[preferences,requests]}` 형식이고, 출력에는 `"ocean"`처럼 JSON 문자열을 씁니다. 세 번째와 다섯 번째 문항은 `{"args":[sticker,target]}` 형식이며 출력은 최소 교환 횟수 또는 불가능할 때 `-1`인 JSON 정수입니다. 네 번째 문항은 `{"args":[numbers]}` 형식이며 출력은 `[왼쪽으로 탈출한 개수, 오른쪽으로 탈출한 개수]`인 정수 두 개의 JSON 배열입니다. 대형 입력의 파일 크기를 줄이기 위해 들여쓰기를 넣지 않습니다. 같은 출력 디렉터리에서 다시 실행하면 해당 번호의 파일을 덮어씁니다.

Python에서 직접 사용할 때는 `make_cases("01-square-regions")`, `make_cases("02-ticket-exchange")`, `make_cases("03-sticker-exchange")`, `make_cases("04-number-movement")` 또는 `make_cases("05-sticker-same-column")`를 호출하세요. 각각 다음 구조의 사전 10개가 담긴 목록을 반환합니다.

```python
{"id": "01", "name": "한국어 검증 항목", "args": [...], "expected": ...}
```

큰 입력도 축약 설명이나 파일 경로가 아닌 실제 배열로 반환됩니다. 따라서 전체 목록을 보관할 만큼의 메모리가 필요합니다.

## 문항 1: 완성된 정사각형 타일 묶음

| 번호 | 크기 | 검증 목표 | 기대 출력 |
| --- | --- | --- | --- |
| 01 | `2 × 2` | 최소 격자에서 번호가 서로 다른 한 칸짜리 묶음은 모두 제외 | `0` |
| 02 | `4 × 4` | 번호 `0~3`의 독립된 `2 × 2` 묶음 네 개를 각각 계산 | `4` |
| 03 | `3 × 3` | 전부 번호 `7`인 하나의 완성품 내부에서 부분 정사각형을 중복 계산하지 않음 | `1` |
| 04 | `4 × 9` | `2 × 2`, `3 × 3`, `4 × 4` 정사각형을 각각 세고 나머지 직사각형은 제외 | `3` |
| 05 | `3 × 3` | 테두리의 번호가 같아도 가운데 타일이 다른 번호이면 해당 묶음은 미완성 | `0` |
| 06 | `2 × 3` | 빈틈없는 직사각형이어도 가로와 세로 길이가 다르면 제외 | `0` |
| 07 | `2 × 2` | 번호 `0`도 유효한 타일 번호이며 최소 크기의 완성품으로 계산 | `1` |
| 08 | `1,000 × 1,000` | 최대 크기의 단일 연결 묶음: 재귀 깊이, 전체 순회 비용과 메모리 확인 | `1` |
| 09 | `1,000 × 999` | 큰 묶음을 끝까지 확인하되 정사각형이 아닌 경우 제외 | `0` |
| 10 | `1,000 × 1,000` | 독립된 `2 × 2` 완성품 25만 개: 많은 묶음의 처리 비용과 큰 반환값 확인 | `250000` |

10번은 위치 `(r, c)`의 번호를 `2 * ((r // 2) % 2) + ((c // 2) % 2)`로 정합니다. 인접한 `2 × 2` 블록은 대각선 방향까지 모두 번호가 다르므로 서로 연결되지 않습니다. `500 × 500`개의 블록이 각각 완성품이 됩니다. 두 번호만 번갈아 배치하면 같은 번호의 블록들이 대각선으로 이어지므로 이 목적에 맞지 않습니다.

## 문항 2: 가장 마음에 드는 체험 부스

`P`는 선호 목록의 부스 수, `R`은 제안 수입니다. 마감 시각 포함, 선호도 하락 허용, 목록 밖 이름이 포함된 제안 전체 제외, 이름의 대소문자 구분 규칙을 적용합니다.

| 번호 | 크기 | 검증 목표 | 기대 출력 |
| --- | --- | --- | --- |
| 01 | `P=4`, `R=3` | 기억 예제를 `art → robot → space → ocean`으로 바꾼 기본 연쇄 | `"ocean"` |
| 02 | `P=3`, `R=2` | `10:00`에 얻은 이용권으로 `10:00`에 마감되는 제안을 즉시 이용 | `"space"` |
| 03 | `P=4`, `R=4` | `10:01` 도착으로 `10:00` 마감을 놓친 경우와 미등록 부스 `ghost`를 경유하는 가짜 경로 제외 | `"robot"` |
| 04 | `P=7`, `R=6` | 입력은 교환 순서의 역순이어도 `12:00`에 여섯 번 연속 교환 가능 | `"ocean"` |
| 05 | `P=4`, `R=3` | `art → space → robot → ocean`에서 중간 선호도 하락 허용 | `"ocean"` |
| 06 | `P=4`, `R=4` | `00:00`에 출발해 대기하며 이동, 순환 제안 처리, `23:59` 마감 형식 확인 | `"ocean"` |
| 07 | `P=4`, `R=4` | 늦은 직행으로 먼저 발견한 부스의 도착 시각을 빠른 우회 경로로 갱신 | `"ocean"` |
| 08 | `P=2`, `R=1` | 부스 수와 제안 수의 최소 경계, 교환 방향 및 대소문자 구분, 교환하지 않는 선택 | `"art"` |
| 09 | `P=3,000`, `R=3,000` | 역순으로 주어진 길이 2,999의 연쇄와 시작점으로 돌아오는 순환 | `"belj"` |
| 10 | `P=3,000`, `R=3,000` | 많은 분기와 같은 두 부스 사이의 제안 여러 개를 처리하며 가장 빠른 도착을 유지 | `"belj"` |

9번과 10번의 부스 이름은 모두 서로 다른 소문자 네 글자이며, `baaa`부터 `belj`까지 생성합니다. 입력에 숫자가 들어간 이름을 사용하지 않습니다. 모든 제안은 `00:00~23:59` 범위에서 시작이 마감보다 빠릅니다.

9번은 `baaa`에서 시작하는 모든 연쇄 제안이 같은 시간 구간에 유효하므로 끝 부스 `belj`에 도착할 수 있습니다. 제안 순서대로 한 번만 검사하는 풀이와 연쇄를 재귀로만 처리하는 풀이를 점검할 수 있습니다.

10번은 시작점에서 두 번째 부스로 가는 제안을 늦은 것, 빠른 것 순서로 놓습니다. 빠른 제안으로 `00:00`에 두 번째 부스를 얻으면 `09:00`에 최상위 부스 `belj`로 이동할 수 있습니다. 나머지 2,997개 제안은 시작점에서 다른 부스로 뻗는 분기입니다.

## 문항 3: 스티커 교환 (다른 열 허용)

`N`은 사람 수(행 수), `M`은 각 사람의 스티커 수(열 수)입니다. 같은 행의 두 위치를 직접 교환할 수 없으며, 이미 목표와 같은 위치도 교환에 사용할 수 있습니다. 목표에 도달할 수 없는 입력도 포함하며, 이때는 `-1`을 반환합니다. 원래 시험에서 같은 열끼리만 교환했는지는 확인되지 않았습니다. 이 연습판의 테스트는 **서로 다른 행이라면 서로 다른 열끼리도 교환 가능**하다는 가정을 따릅니다. 01~08번은 문제 설명의 자체 연습 예제와 같습니다.

| 번호 | 크기 | 검증 목표 | 기대 출력 |
| --- | --- | --- | --- |
| 01 | `2 × 1` | 모든 위치가 이미 목표와 같으면 교환하지 않음 | `0` |
| 02 | `2 × 2` | 다른 행의 같은 열에 있는 두 스티커 교환 | `1` |
| 03 | `2 × 3` | 같은 행 안의 이동에서 다른 행을 거침 | `2` |
| 04 | `2 × 4` | 한 행의 네 위치가 다르고 다른 행은 처음부터 목표와 같은 경우 | `4` |
| 05 | `2 × 5` | 서로 다른 열끼리도 교환 가능 | `3` |
| 06 | `3 × 4` | 세 행에 걸쳐 모든 위치를 목표와 일치시킴 | `6` |
| 07 | `1 × 2` | `[[1,0]]`을 `[[0,1]]`로 바꿔야 하지만 서로 다른 두 행을 고를 수 없음 | `-1` |
| 08 | `2 × 2` | `[[1,0],[0,0]]`을 전부 `0`인 목표로 만들 수 없음 | `-1` |
| 09 | `2 × 2` | 전부 `0`인 입력을 `[[1,0],[0,0]]`인 목표로 만들 수 없음 | `-1` |
| 10 | `1 × 10` | `[0,1]`이 다섯 번 반복된 한 행이 처음부터 목표와 같음 | `0` |

모든 입력은 `1 ≤ N, M ≤ 10`, `N × M ≤ 12`를 만족합니다. `N × M ≤ 12`는 작은 전체 배치를 직접 탐색하도록 추가한 **연습용 제한**이며, 원래 시험의 정확한 제한은 확인되지 않았습니다. 06번은 전체 12칸, 10번은 한 행의 최대 길이 10칸인 경계 입력입니다. 이전 연습판의 100,000칸 입력은 이번 범위에 맞춰 교체했습니다. 같은 열만 허용하는 별도 규칙은 문항 5에서 연습합니다.

## 문항 4: 숫자의 이동과 합치지

`N`은 처음 주어진 배열의 길이입니다. 양수는 오른쪽으로, 음수는 왼쪽으로 동시에 한 칸 이동한 뒤 **같은 칸에 도착한 숫자끼리만** 합쳐집니다. 반환 순서는 `[왼쪽, 오른쪽]`이며 합쳐진 숫자가 탈출하면 하나로 셉니다. 01~06번은 문제 설명의 자체 연습 예제와 같습니다.

| 번호 | 크기 | 검증 목표 | 기대 출력 |
| --- | --- | --- | --- |
| 01 | `N=1` | `[0]`은 처음부터 빈 칸이며 탈출하지 않음 | `[0, 0]` |
| 02 | `N=2` | `[1,-1]`은 엇갈려 지나간 뒤 각각 탈출 | `[1, 1]` |
| 03 | `N=3` | `[3,0,-3]`은 같은 칸에서 합이 `0`이 되어 소멸 | `[0, 0]` |
| 04 | `N=3` | `[5,0,-3]`은 `2` 하나가 되어 오른쪽으로 탈출 | `[0, 1]` |
| 05 | `N=3` | `[2,0,-5]`은 `-3` 하나가 되어 왼쪽으로 탈출 | `[1, 0]` |
| 06 | `N=5` | `[4,0,3,0,-5]`에서 음수로 합쳐진 숫자가 다시 합쳐져 오른쪽으로 탈출 | `[0, 1]` |
| 07 | `N=7` | `[-1,0,3,0,-3,0,1]`의 양쪽 탈출과 가운데 합 `0` 소멸이 같은 시간에 발생 | `[1, 1]` |
| 08 | `N=100,000` | 전부 `10^9`인 숫자가 합쳐지지 않고 오른쪽으로 각각 탈출 | `[0, 100000]` |
| 09 | `N=100,000` | `[10^9,-10^9]`를 50,000번 반복해 엇갈림과 양쪽 탈출 개수 확인 | `[50000, 50000]` |
| 10 | `N=100,000` | 앞쪽 50,000칸이 `10^9`, 뒤쪽 50,000칸이 `-10^9`이며 모두 합 `0`으로 소멸 | `[0, 0]` |

08~10번은 연습용 길이 상한과 값의 경계를 사용합니다. 원래 시험의 입력 상한은 확인되지 않았습니다. 시간·메모리 제한은 사용자가 **10초·2GB**로 기억한 내용이며 공식 제한을 확인한 것이 아닙니다. 채점할 때 `--timeout 10`을 지정할 수 있고, 이 로컬 채점기는 2GB 메모리 상한을 강제하지 않습니다.

## 문항 5: 스티커 교환 (같은 열만)

서로 다른 두 행의 **같은 열**에 있는 스티커만 맞바꿀 수 있습니다. 목표에 도달할 수 없으면 `-1`을 반환합니다. 원래 시험의 열 교환 규칙은 아직 확인되지 않았으므로, 문항 3과 분리한 연습용 문제입니다. 01~06번은 이 문제 설명의 자체 연습 예제와 같습니다.

| 번호 | 크기 | 검증 목표 | 기대 출력 |
| --- | --- | --- | --- |
| 01 | `2 × 1` | 모든 위치가 이미 목표와 같음 | `0` |
| 02 | `2 × 2` | 같은 열의 두 행에서 스티커 하나씩 교환 | `1` |
| 03 | `2 × 2` | `[[1,0],[0,0]]`을 `[[0,0],[0,1]]`로 바꾸려면 다른 열로 옮겨야 하므로 불가능 | `-1` |
| 04 | `3 × 2` | 두 열에 걸쳐 세 행의 배치를 두 번 교환해 맞춤 | `2` |
| 05 | `2 × 3` | 서로 다른 세 열에서 각각 한 번 교환 | `3` |
| 06 | `3 × 4` | 네 열에 걸쳐 세 행의 배치를 네 번 교환해 맞춤 | `4` |
| 07 | `1 × 2` | `[[1,0]]`을 `[[0,1]]`로 바꿀 수 없음 | `-1` |
| 08 | `2 × 2` | `[[1,0],[0,0]]`을 전부 `0`인 목표로 만들 수 없음 | `-1` |
| 09 | `10 × 10` | 위쪽 다섯 행은 모두 `1`, 아래쪽 다섯 행은 모두 `0`인 배치를 반대로 바꿈 | `50` |
| 10 | `1 × 10` | `[0,1]`이 다섯 번 반복된 한 행이 처음부터 목표와 같음 | `0` |

연습용 범위는 `1 ≤ N, M ≤ 10`이며, 문항 3의 전체 12칸 제한은 적용하지 않습니다. 09번은 100칸인 연습용 최대 입력입니다. 원래 시험에서 `N`, `M` 각각에 작은 제한이 있었다는 기억을 바탕으로 정한 연습 범위이며, 정확한 상한이나 열 교환 규칙을 확인한 것은 아닙니다.

## 경계와 실행 시간 확인

- 정확성은 각 테스트의 실제 반환값을 기대 출력과 비교해 확인합니다.
- 문항 1의 08~10번은 최대 격자에서 연결 묶음 하나와 묶음 25만 개를 각각 처리하게 합니다.
- 문항 2의 09~10번은 부스 수와 제안 수를 모두 상한까지 사용하며 긴 연쇄, 순환, 분기, 평행 제안을 포함합니다.
- 문항 3은 전체 최대 12칸의 배치에서 최소 교환 횟수와 불가능한 입력의 `-1` 반환을 확인합니다. 06번은 전체 칸 수, 10번은 열 수의 연습용 경계입니다.
